# goit-rdb-fp - фінальний проєкт: `pandemic.infectious_cases`

Фінальний проєкт курсу з реляційних баз даних. Дані про інфекційні захворювання (`infectious_cases.csv`) імпортовано в PostgreSQL, нормалізовано до 3НФ і проаналізовано SQL-запитами та власними функціями.

## Структура репозиторію

```
goit-rdb-fp/
├── pandemic_final_project.ipynb   # notebook з усіма виконаними запитами та output-ами
├── sql/
│   └── pandemic_project.sql       # той самий SQL одним файлом (запуск через psql)
├── data/
│   └── infectious_cases.csv       # вихідний датасет
├── screenshots/                   # скриншоти таблиць, запитів і результатів
└── README.md
```

## Як запустити

**Варіант 1. Notebook (Jupyter або Google Colab).** PostgreSQL 16 запускається всередині notebook через `pgserver`, окремий сервер не потрібен.
1. Відкрийте `pandemic_final_project.ipynb`.
2. Переконайтеся, що `infectious_cases.csv` лежить у `data/` або поруч із notebook. У Colab, якщо файл не знайдено, з'явиться діалог завантаження.
3. Виконайте *Restart & Run All*.

**Варіант 2. psql** (PostgreSQL 15+, бо використовується `UNIQUE NULLS NOT DISTINCT`):
```bash
psql -d <database> -f sql/pandemic_project.sql   # запускати з кореня репозиторію
```
CSV імпортується командою `\copy` зі шляху `data/infectious_cases.csv`.

## Виконання завдань

### 1. Завантаження даних - [скриншоти 01–04](screenshots/)
- `CREATE SCHEMA IF NOT EXISTS pandemic;` і `SET search_path TO pandemic;` (схема за замовчуванням). Результат підтверджує `SHOW search_path`.
- Таблиця `infectious_cases` створюється як staging-таблиця з колонками `TEXT`, бо в CSV відсутні значення записані порожніми рядками. Дані імпортуються командою `COPY … WITH (FORMAT csv, HEADER true)`.
- Огляд даних: перші 10 рядків, кількість рядків, сутностей, рядків без `Code`, діапазон років і кількість заповнених значень по кожній хворобі.

### 2. Нормалізація до 3НФ - [скриншоти 05–08](screenshots/)

| Таблиця | Призначення | Ключі |
|---|---|---|
| `entities` | унікальні комбінації `Entity` + `Code` | `id` PK; `UNIQUE NULLS NOT DISTINCT (entity, code)` |
| `infectious_cases_normalized` | показники захворювань за роками | `id` PK; `entity_id` FK -> `entities(id)`; `UNIQUE (entity_id, year)` |

- **1НФ:** усі значення атомарні; на рядок припадає одна сутність і один рік.
- **2НФ / 3НФ:** `Code` залежить від `Entity`, а не від року. Тому пара `Entity`/`Code` винесена в `entities`, а в таблиці показників залишився лише `entity_id`. Показники залежать тільки від ключа `(entity_id, year)`, транзитивних залежностей немає.
- Під час нормалізації текст перетворюється на типи: `year` -> `INTEGER`, показники -> `NUMERIC`. Порожні значення стають `NULL` (допоміжна функція `try_numeric`), а не `0`, щоб не спотворювати середні.
- Перевірка: кількість рядків збігається з оригіналом, а `EXCEPT` між оригіналом і `JOIN` нормалізованих таблиць дає **0 розбіжностей**.

### 3. Аналіз `Number_rabies` - [скриншот 09](screenshots/09_rabies_stats.png)
`AVG`, `MIN`, `MAX`, `SUM` по кожному `entity_id` (з назвою та кодом). Беруться лише рядки з наявним значенням. Результат відсортовано за середнім за спаданням, `LIMIT 10`.

### 4. Колонка різниці в роках - [скриншот 10](screenshots/10_year_diff_builtin.png)
- `MAKE_DATE(year, 1, 1)` - 1 січня відповідного року;
- `CURRENT_DATE` - поточна дата;
- `EXTRACT(YEAR FROM AGE(CURRENT_DATE, MAKE_DATE(year, 1, 1)))` - різниця в повних роках.

> Результат залежить від дати запуску, тому числа на скриншотах відповідають даті виконання notebook.

### 5. Власні функції — [скриншоти 11–16](screenshots/)
- **`fn_years_since(p_year INTEGER) -> INTEGER`**: рік -> 1 січня цього року -> різниця в роках із `CURRENT_DATE` (приклад: `1996 -> 1996-01-01 -> …`). Функція оголошена як `STABLE`, бо залежить від поточної дати. Її використано в запиті до таблиці, а перевірка по всіх рядках показала **0 розбіжностей** з розрахунком із Завдання 4.
- **`fn_avg_cases_per_period(p_cases_per_year NUMERIC, p_divider NUMERIC) -> NUMERIC`**: кількість захворювань за рік, поділена на дільник. Дільник `0` або `NULL` викликає зрозумілу помилку. Функцію використано з дільниками **12** (місяць), **4** (квартал) і **2** (півріччя). У функцію передаються **лише числові** значення `Number_rabies`: їх відбирає фільтр `WHERE number_rabies ~ '^\s*-?[0-9]+(\.[0-9]+)?([eE][-+]?[0-9]+)?\s*$'`.
